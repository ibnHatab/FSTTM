# Go2 Natural-Language Intent and Semantic Navigation Specification

A small intent language between the LLM and the robot — the LLM never
generates navigation actions directly. Modeled on the modular GOAT /
HomeRobot philosophy: goal specification → semantic memory/map → long-term
goal → classical local navigation. HomeRobot separates hierarchical skills
such as `NAV_TO_OBJ`, `NAV_TO_INSTANCE`, `EXPLORE`; the HomeRobot challenge
targets open-vocabulary natural-language goals in unfamiliar environments.

## 1. Architecture

The language system does **not control the robot directly**.

```text
Speech
  │
  ▼
Whisper
  │
  ▼
LLM
  │
  ▼
Intent specification
  │
  ├── local robot action ───────► Go2 action interface
  │
  ├── semantic query ───────────► semantic map / object memory
  │
  └── navigation goal ──────────► classical navigation stack
                                      │
                                      ▼
                                   Nav2 / planner
```

The LLM is responsible for translating human language into a constrained
intent representation. The planner, perception system and robot controller
remain deterministic.

This follows the modular philosophy of GOAT: the semantic system identifies a
target or exploration goal, while a classical local navigation policy handles
motion. GOAT uses a top-down semantic map plus persistent object-instance
memory, then sends a point-navigation goal to the local planner.

## 2. Intent categories

The top-level intent should be one of:

```text
LOCAL_ACTION
QUERY
NAVIGATE
FIND
FOLLOW
STOP
CANCEL
UNKNOWN
```

### LOCAL_ACTION

Immediate Go2 action that does not require semantic navigation.

Examples: stand up, sit down, stretch, shake, jump, turn around, move
forward, move backward, rotate left, rotate right.

These correspond to the low-level wireless-controller/action interface. The
Go2 interface exposes `lx` (left/right translation), `ly` (forward/backward
translation), `rx` (rotation), `ry` (right-stick vertical), `keys`
(button/action state), and named actions such as stand-up, stretch, shake
hands, love, pounce and jump-forward.

The LLM should never output arbitrary shell commands or arbitrary ROS
messages.

## 3. Local action schema

```json
{"intent": "LOCAL_ACTION", "action": "STAND_UP", "duration": null}
```

```json
{"intent": "LOCAL_ACTION", "action": "STRETCH"}
```

```json
{"intent": "LOCAL_ACTION", "action": "TURN", "direction": "LEFT", "angle_deg": 90}
```

```json
{"intent": "LOCAL_ACTION", "action": "VELOCITY",
 "linear_x": 0.3, "linear_y": 0.0, "angular_z": 0.0, "duration": 2.0}
```

For safety, `VELOCITY` should normally be generated by the planner/controller
rather than by the LLM.

## 4. QUERY

A query asks the robot to identify something in its semantic representation.

Examples: "What objects are near me?", "Where is the chair?", "Is there a
fire extinguisher here?", "Find all doors.", "What is next to the table?",
"Which chair is closest to the window?"

```json
{"intent": "QUERY",
 "target": {"type": "OBJECT", "description": "chair"},
 "spatial_constraint": null}
```

**QUERY does not necessarily move the robot.** It interrogates the current
semantic map/object memory.

## 5. Semantic target representation

Do not reduce the target to only a closed class name. Use:

```json
{"type": "OBJECT",
 "class": "chair",
 "description": "an office chair",
 "attributes": {"color": "black", "size": null, "material": null}}
```

`class` is optional. `description` is important. This allows "chair",
"office chair", "black office chair", "the chair with wheels", "something
suitable for sitting" to all become semantic queries. The perception system
can resolve these against detector classes, DINOv3 features, or future
open-vocabulary embeddings.

## 6. NAVIGATE

Navigation should be expressed as a **goal**, never as a sequence of velocity
commands.

```json
{"intent": "NAVIGATE", "goal": {"type": "OBJECT", "description": "chair"}}
```

The semantic subsystem resolves: language goal → semantic query → object
instances → 3D position → navigation goal. Then the classical navigation
stack takes over. Object instances are localized in a top-down semantic map
and the selected instance becomes a long-term point-navigation goal (GOAT).

## 7. NAVIGATE with spatial relations

> Go to the chair next to the window.

```json
{"intent": "NAVIGATE",
 "goal": {"type": "OBJECT", "description": "chair"},
 "constraints": [
   {"relation": "NEAR",
    "reference": {"type": "OBJECT", "description": "window"}}]}
```

> Go to the table in front of the sofa.

```json
{"intent": "NAVIGATE",
 "goal": {"type": "OBJECT", "description": "table"},
 "constraints": [
   {"relation": "IN_FRONT_OF",
    "reference": {"type": "OBJECT", "description": "sofa"}}]}
```

The semantic-map layer resolves these relations. The LLM does not need to
know the coordinates.

## 8. NAVIGATE TO LOCATION

Not every navigation target is an object. Support target types:

```text
POSITION  OBJECT  REGION  ROOM  LANDMARK  PERSON
```

Examples: "go to the kitchen", "go to the entrance", "go to the other side
of the room", "go back", "go home", "go to where we started".

```json
{"intent": "NAVIGATE", "goal": {"type": "REGION", "description": "entrance"}}
```

## 9. Semantic query interface

The semantic layer exposes a small API to the planner:
`query(target, constraints) → candidates[]`

```json
{"target": {"description": "chair"}}
```

returns:

```json
[{"instance_id": 17, "score": 0.93, "position": [4.2, 1.7, 0.0],
  "last_seen": 12.3, "confidence": 0.94},
 {"instance_id": 31, "score": 0.81, "position": [8.1, -2.2, 0.0],
  "last_seen": 4.1, "confidence": 0.88}]
```

The planner then chooses which instance to visit.

## 10. Semantic map

The map should contain both geometry and semantics:

```text
SemanticMap
├── occupancy / traversability
├── object instances
│    ├── instance_id, semantic class, embedding, 3D position,
│    ├── bounding box, confidence
│    └── observations
├── regions (room, corridor, entrance)
└── landmarks
```

Closer to GOAT's semantic map + Object Instance Memory than a pure object
detector: keep observations of previously seen instances so the robot can
return to a particular instance later.

## 11. Object instance memory

Do not store only `chair = position`. Store:

```json
{"instance_id": 42, "class": "chair", "embedding": "...",
 "position": [4.1, 2.3, 0.0],
 "observations": [
   {"position": [3.9, 2.0], "timestamp": 1234},
   {"position": [4.1, 2.3], "timestamp": 1291}]}
```

This lets "Go to that chair I saw earlier." become an instance query rather
than a class query — distinguishing individual instances of the same category
is important for language/image goals (GOAT).

## 12. FIND

`FIND` is different from `NAVIGATE`:

```text
FIND     = search for an object
NAVIGATE = go to an already-resolved goal
```

> Find a chair.

```json
{"intent": "FIND", "target": {"type": "OBJECT", "description": "chair"}}
```

The semantic navigation system then:

```text
known instance?
     │
 ┌───┴────┐
yes       no
 │         │
go there   explore
```

If an instance has been localized, navigate to it; otherwise produce an
exploration goal (GOAT uses frontier-based exploration for this fallback).

## 13. FOLLOW

```json
{"intent": "FOLLOW", "target": {"type": "PERSON", "description": "the person"}}
```

Special case: the target is dynamic. The semantic map should not convert it
into a permanent navigation goal. Instead: detector / tracker → target pose →
local controller.

## 14. STOP / CANCEL

These bypass semantic reasoning; the robot controller executes them
immediately.

```json
{"intent": "STOP"}
```

```json
{"intent": "CANCEL"}
```

## 15. Exploration

Exploration is a planner operation, not an LLM action primitive. The LLM can
request a FIND; the planner decides:

```text
object not known → semantic exploration → frontier / informative viewpoint
→ classical navigation → perception → semantic map update
```

Modular approach per Gervet et al.: build a geometric/semantic map, select
exploration goals, use an analytical planner. Real-world evaluation found
modular learning substantially more reliable than end-to-end navigation.

## 16. Navigation commands

Keep the navigation command vocabulary extremely small:

```text
GO_TO  FIND  FOLLOW  RETURN  EXPLORE  STOP  CANCEL
```

Do NOT expose "turn 17 degrees", "move 0.32 m", "rotate at 0.2 rad/s" to the
LLM. Those belong below the intent layer.

## 17. Navigation goal output

The semantic/planning layer ultimately produces:

```json
{"goal_type": "POSE", "position": [4.21, 2.17, 0.0], "yaw": 1.57,
 "source": "semantic_object", "instance_id": 42}
```

Then Nav2 / the classical planner handles the actual path — GOAT's separation
between semantic goal selection and local navigation.

## 18. LLM responsibility

The LLM should do only:

```text
natural language → intent → structured semantic description
```

It should NOT: calculate robot coordinates, generate velocity commands,
select paths, manipulate the occupancy grid, decide collision avoidance,
directly publish ROS topics, execute shell commands.

> "Go find the red chair near the window."

```json
{"intent": "FIND",
 "target": {"type": "OBJECT", "description": "chair",
            "attributes": {"color": "red"}},
 "constraints": [
   {"relation": "NEAR",
    "reference": {"type": "OBJECT", "description": "window"}}]}
```

Everything after that is robotics.

## 19. Overall Go2 stack

```text
                    USER
                      │
                   speech
                      │
                      ▼
                  Whisper
                      │
                      ▼
                  small LLM
                      │
                Intent JSON
                      │
        ┌─────────────┼──────────────┐
        │             │              │
        ▼             ▼              ▼
   LOCAL_ACTION     QUERY          NAVIGATION
        │             │              │
        ▼             ▼              ▼
   Go2 action     semantic map    semantic query
                                      │
                                      ▼
                                object memory
                                      │
                                      ▼
                                  3D target
                                      │
                                      ▼
                                Nav2 / planner
                                      │
                                      ▼
                                  Go2 motion
```

Perception is independent:

```text
X5 ──────────────► DINOv3-S / detector
                         │
L1 LiDAR ────────────────┤
                         ▼
                    3D semantic map
                         │
                         ▼
                  object instance memory
```

The key concept is **not "LLM controls the dog."** It is:

> **LLM produces an intent; semantic perception resolves the intent into a
> spatial goal; classical navigation executes the goal.**

The stable ROS2 interface is **`Intent → SemanticQuery → NavigationGoal`**,
with the Go2 wireless-controller interface remaining only at the bottom of
the stack.
